# CoffeeBear：NAS 运行 + 云端唯一数据源（2026-10-22 已确认目标）

> 决策：DEC-004；跟踪 Issue #59。**本文件描述目标架构，不表示当前 NAS/Production 已完成切换。**

## 1. 目标部署

```text
                    GitHub / GHCR 已验收不可变镜像
                              |
                      同版本应用程序
             +----------------+----------------+
             |                                 |
        NAS 本地 Coffee API                云服务器备用 Coffee API
        （日常业务入口）                    （切换后接管流量）
             |                                 |
             +----------------+----------------+
                              |
                 Production 唯一数据源
               +--------------+--------------+
               |              |              |
       Supabase PostgreSQL   Cloudflare R2  统一云端 Redis*
         订单/库存/财务       业务文件/附件      Celery 队列
               |              |              |
               +--------------+--------------+
                              |
                  单一 Celery beat / 迁移执行者
```

*Redis 提供方尚未实机核对，实施时确定可持续访问且具备身份验证/TLS 的托管 Redis。NAS 本地 Redis 不能在云备机无障碍接管时成为唯一队列事实源。*

- 保留 Test / Production 两环境，不新增第三套业务环境：NAS 与云备机是 **同一 Production 的两个计算节点**。
- 在 NAS 内存不足情况下，采用 GHCR **预构建**镜像；不在 NAS 上 `docker compose build`，不要求近期升级内存。
- 用一套 `DATABASE_URL` + R2 业务 bucket + `REDIS_URL`，应用会话密钥/版本一致；限制云备入口/切换机制，禁止无人看管的双端同时执行迁移和定时任务。
- 业务对象存储与 R2 **备份归档**是两种用途：请使用独立前缀或存储桶和最小权限，不能把 `R2_BACKUP_*` 冒充应用文件读写功能。

## 2. 当前事实（仓库核查，不代表 NAS 实时配置）

- `deploy/zspace/docker-compose.yml` 仍启动 `postgres` 和 `redis`，且 API/worker/beat 依赖它们；`production.env.example` 默认连接 `postgres:5432`。
- 应用使用 `DATA_DIR=/data` 的宿主机挂载目录；包括上传附件、导入与导出文件、备份/浏览器登录会话等路径，需要逐一归类并改造业务对象引用。
- 现有 `R2_BACKUP_*` 仅能说明存在 R2 备份配置，不能说明业务文件已直接存取 R2。
- `deploy/update-q4.sh` 依赖 `docker compose exec postgres pg_dump`，切换云数据库之前必须换成经过测试的远端备份与恢复步骤。
- 仓库历史文档还写了 Cloud Run / Neon 主用；现按维护者 2026-10-22 的新决策将它们保留为历史参考，不视为当前正式部署实况。
- NAS 当前实际 `.env`、SQL 数据和上传文件数量/路径、云数据库连接情况未验证。**禁止对未知生产数据执行覆盖。**

## 4. 故障边界

- 统一一份云 PostgreSQL/R2 可以避免两个计算节点之间的业务数据分叉，**但不等于高可用数据库**：NAS 到云网络断开仍可能无法使用。
- 云备机运行代码 ≠ 自动同步旧版程序：两个节点必须统一已验证镜像并提供迁移兼容窗口。
- R2 数据不因切换应用服务器而丢失的前提是**每条生产业务文件操作都确实走 R2**；本地 `DATA_DIR` 暂存内容可能无法跨节点读取。
- 应用回滚和数据库 schema / 数据回滚不是同一件事。
