# CoffeeBear 架构方向

## 定位

CoffeeBear 是“卖咖啡的熊”的国内经营系统，只承载中国境内业务。

本仓库的长期边界固定为：

- 国内采购与供应链
- 1688 采购接入
- 吉客云 / JackYun 数据接入
- 国内库存、生产与耗材流转
- 国内销售、售后、物流
- 往来单位、银行、税务、发票、回款与月结
- 国内经营分析、备份、更新与自动化

`jinfenghua1990/ALSVID` 是自行车 / 出口 / 欧洲业务的唯一实现仓库。CoffeeBear 不承载 ALSVID、Dealer Portal、Shopify 外贸订单、出口物流、欧洲库存或出口财务。

## 核心底座

### Business Partner

作为国内供应商、客户、工厂及其他往来主体的统一身份中心。采购、付款、发票、银行流水等事实通过主体 ID 关联，避免名称差异造成数据断裂。

### Product / SKU

维护卖咖啡的熊国内商品、SKU、耗材、套装、分类、成本与库存相关主数据。ALSVID 自行车产品、BOM、车辆和配件主数据不进入本仓库。

### 国内供应链

以 1688、吉客云和人工事实为来源，覆盖采购、生产、到货、入库、库存、物流和结算。不得为了外贸场景扩展第二套出口供应链。

### 国内财务

以国内业务事实形成 FinanceEntry、回款、银行、税务、发票、费用、利润和月结结果。历史数据库中可能仍存在拆分前的外贸表或行，但它们不是当前业务 authority，不得重新暴露为运行功能。

## 明确不属于 CoffeeBear

以下能力不得在本仓库新增或恢复：

- ALSVID 产品平台 FC / FT / CT / GT
- 自行车 BOM、Vehicle、Frame Number、Warranty、ServiceCase
- Dealer / 经销商门户
- My ALSVID
- Shopify OMS 或外贸订单工作台
- 中国工厂 → 德国仓 / 欧洲经销商的出口物流
- 德国 / 奥地利 / 欧盟库存
- EORI、关税、进口 VAT、出口退税等出口合规与财务
- ALSVID 官网、售后门户或欧洲客户体系

这些能力只进入 `jinfenghua1990/ALSVID`。

## 迁移规则

仓库拆分遵循“迁移一个，旧位置删除一个”：

1. 新仓能力完成并通过测试；
2. 数据 / 接口切换完成；
3. 旧仓对应运行代码、路由、UI、测试和误导性文档立即删除；
4. 不保留双 authority 或长期兼容壳。

Alembic 历史迁移属于数据库升级链，不等同于当前业务运行代码。需要删除历史 schema 时，先建立安全 baseline / cutover，再删除旧迁移链，禁止直接破坏已有数据库升级路径。

## 架构决策原则

任何新增功能必须先确认：

1. 是否明确属于卖咖啡的熊国内业务；
2. 是否已有唯一事实源；
3. 是否会重复现有模型、service 或报表口径；
4. 是否会把 ALSVID / 出口边界重新引入 CoffeeBear；
5. 是否符合自然月、Decimal、审计和幂等规则。

与 `docs/ARCHITECTURE.md` 冲突时，以更严格的 domestic-only 边界为准。
